# Правила игры

> Файл для игровых правил. Будет дополняться — при добавлении или изменении
> правил обновлять этот файл.

## Кубик

Кубик (`Game::Die`, `src/die.h`) имеет шесть граней: `1`, `0`, `i`, `-i`, `-`, `+`.

Через кубик проходят три оси, каждая — через пару противоположных граней.
Поворот вокруг оси не меняет две грани, лежащие на ней, и циклически
перебирает остальные четыре.

| Ось | Цвет | Грани на оси |
|---|---|---|
| X | синий | `+`, `-` |
| Y | зелёный | `i`, `-i` |
| Z | жёлтый | `0`, `1` |

Разрешённые повороты: 90, -90 и 180 градусов вокруг любой оси.

Циклы граней при повороте на +90 (на -90 — в обратном порядке, 180 — два шага):

| Ось | Цикл (+90) |
|---|---|
| X | `i` → `0` → `-i` → `1` → `i` |
| Y | `+` → `1` → `-` → `0` → `+` |
| Z | `+` → `-i` → `-` → `i` → `+` |

## Регистр

Регистр (`Game::Register`, `src/register.h`) — набор из фиксированного числа
кубиков. Количество задаётся при создании, начальные состояния кубиков
случайны.

Два регистра равны, только если совпадает количество кубиков и состояние
каждого кубика на той же позиции (порядок важен).

## Состояние игры

Состояние игры (`Game::GameState`, `src/game_state.h`) хранит:

- id игроков;
- регистр каждого игрока (по одному, порядок как в списке id);
- целевой регистр;
- номер игрока, который ходит сейчас (индекс в списке id);
- счётчик карт, сыгранных текущим игроком в этом ходу;
- список id меток уже сыгранных карт (физическая карта играется раз за игру);
- историю карт, сыгранных на каждый кубит (для будущей карты, отменяющей
последнюю; в `setGameState` передаётся только последняя карта на кубит).

При создании состояния задаётся список id игроков и число кубиков в регистрах.
Все регистры — и игроков, и целевой — изначально случайны. Первым ходит игрок
с индексом 0, счётчик карт хода — 0, список сыгранных карт пуст.

## Карты

Каждая RFID-метка сопоставлена типу карты (`Game::CardRegistry`,
`src/card_registry.h`). Типы:

| Тип | Название |
|---|---|
| `CardType::PauliX` | `pauli_x` |
| `CardType::PauliY` | `pauli_y` |
| `CardType::PauliZ` | `pauli_z` |
| `CardType::PauliX3` | `pauli_x3` |
| `CardType::PauliY3` | `pauli_y3` |
| `CardType::PauliZ3` | `pauli_z3` |

Соответствие id метки и типа изначально захардкожено (шесть записей-заглушек),
но реестр можно менять во время работы (`set`/`remove`) и сохранять в
энергонезависимую память контроллера (`save`/`load`). Сохранённая копия
имеет приоритет над захардкоженной.

## Пополнение реестра

Клиент отправляет ws-событие `writeCard` с названием типа карты. Если тип
существует, контроллер переходит в режим ожидания: следующая метка,
считанная вне игры, регистрируется в реестре за этим типом и сохраняется
в энергонезависимую память. Если метка уже была в реестре, её тип
перезаписывается. После записи отправителю приходит событие `cardWritten`
(`data` не используется). Пустая строка вместо названия типа отменяет
ожидание: контроллер сбрасывает режим, событие при этом не отправляется.

Считывание метки вне игры без активного режима записи ни к чему не приводит
в игре — всем клиентам отправляется событие `cardScanned`: зарегистрирована
ли метка и, если да, тип карты.

## Старт игры

Игра начинается ws-событием `startGame`: в `data` — список id участников
(`players`) и размер регистров (`cubitCount`). Если игра уже идёт,
событие игнорируется.

По событию создаётся новое состояние игры (`GameState`): все регистры,
включая целевой, случайны. Участникам рассылаются `gameStarted` (с тем же
содержимым, что и `startGame`) и затем `setGameState` — полное состояние
игры.

## Выбор кубита

Перед применением карты игрок выбирает кубит ws-событием `selectTarget`:
`player` — номер игрока в игре, `cubit` — номер кубита в его регистре.
Кубит может быть как своим, так и чужим.

Выбор обрабатывается, только если ход отправителя (его id соответствует
текущему игроку в состоянии игры). Выбранный кубит — цель для следующей
считанной карты; выбор можно менять, пока карта не считана. Если считанная
карта требует доп. ввода, цель фиксируется до применения карты: `selectTarget`
игнорируется. При старте новой игры цель сбрасывается.

## Применение карт

Карта применяется, когда её метка считана сканером: игра должна идти и цель
должна быть выбрана (`selectTarget`). Каждая физическая карта может быть
сыграна только один раз за игру — повторное прикладывание игнорируется.

- `pauli_x`, `pauli_y`, `pauli_z` — поворот выбранного кубика на 180° вокруг
  соответствующей оси;
- `pauli_x3`, `pauli_y3`, `pauli_z3` — то же на три соседних кубита, начиная
  с выбранного; у края регистра затрагивается меньше кубитов.

Некоторые карты требуют доп. ввода после считывания: вторую цель или выбор
грани кубита. Такая карта не применяется сразу: текущему игроку отправляется
`cardNeedsInput`, и карта применяется после ответа `cardInput`. Пока ни один
тип карты не требует доп. ввода.

За ход игрок играет 2 карты. После каждой карты счётчик карт хода растёт;
когда достигает 2, ход переходит следующему игроку по кругу, а счётчик
обнуляется. Переход выполняется до отправки состояния клиентам, так что
`setGameState` приходит уже со следующим текущим игроком. После применения
карты цель сбрасывается, участникам уходят события `cardPlayed` (что и куда
применено) и `setGameState` (актуальное состояние). Каждая сыгранная карта
записывается в историю всех кубитов, на которые подействовала (`pauli_*3` —
все кубиты окна); в `setGameState` передаётся только последняя карта на
каждый кубит.

После разыгрывания любой карты регистры игроков сравниваются с целевым
(порядок кубитов важен). При первом совпадении игра заканчивается:
участникам отправляется `gameEnded` с id и именем победителя, ходы и карты
игнорируются до нового `startGame`.

## Сдача

Участник может сдаться ws-событием `giveUp` во время игры. Победителем
объявляется следующий за ним участник по кругу (при двух игроках — другой);
всем участникам отправляется `gameEnded`. Единственный участник при сдаче
просто завершает игру без победителя. События вне игры или от не-участника
игнорируются.
